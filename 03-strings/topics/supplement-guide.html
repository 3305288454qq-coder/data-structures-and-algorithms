串的下标、失败函数与存储约定

本章目录 · T04 对照编码 · T05 nextval · T06 存储手推

pi 和 next 解决同一匹配问题，但不是同一张数值表

pi[i] 是 pattern[0..i] 的最长相等真前后缀长度；i 是 0 基。它描述“这一段已经匹配完以后，能留下多长的边界”。

本套 next[j] 使用 1 基模式位置，表示“第 j 个字符失配时，下次尝试哪个模式位置”；next[1]=0，0 为哨兵。对于 j≥2，它基于失配字符之前的那段，即 pi[j-2]，而不是 pi[j]。返回表第 0 格只是占位。

手推 ababa：先为 a、ab、aba、abab、ababa 写最长真前后缀长度，再为第 1–5 个字符分别写失配跳转位置。特别注意“长度 0”与“模式位置 1”在两个约定中的不同角色。

展开核对三张表

0 基 pi：0,0,1,2,3。

1 基 next（不含占位格）：0,1,1,2,3。

1 基 nextval（不含占位格）：0,1,0,1,0。

因此转换时 j≥2 的 next[j]=pi[j-2]+1，next[1] 单独处理。标准库字符串仍是 0 基，访问第 j 个字符用 pattern[j-1]。

nextval 为什么能跳得更远

如果当前失配字符为 a，而 next 指向的模式字符仍为 a，那么拿同一个文本字符再次和 a 比较必定仍失败；nextval 跳过这次无效尝试。它不跳过可能成功的匹配，也不改变正确的首次匹配位置。对 aaaa 特别明显，但 next 和 nextval 都保持线性时间级别。

不同教材和语言实现也可能使用 0 基、-1 哨兵、前缀长度等约定。不能只看数组名字 next 就断定数值应与本页相同。先明确下标、失配时机和跳转语义，再比较代码。

不混淆空模式的接口

T04/T05 返回首次出现位置，本套约定空模式返回 0。T03 返回全部出现位置，有自己的接口说明。实现前先读题目契约，不把一种返回类型的空模式规则机械套到另一种接口上。
