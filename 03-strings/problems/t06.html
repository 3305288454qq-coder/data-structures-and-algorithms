T06 串的存储与基本操作契约

本章目录 · KMP 下标专题

基础｜手推｜已有阅读页｜学习状态：未开始。前置 T01、T02。

串不是随便一个 char 数组

串是有限字符序列；这里区分“逻辑长度”和“用来存储它的空间”。C 风格字符串通过终止字符 '\0' 判断结束，必须为终止符额外留空间；带长度字段的顺序串由 length 标明有效长度。C++ std::string 维护长度并可以包含 '\0'，处理二进制内容时不要默认 C 接口也会读取同样长度。

任务 A：一个 char 数组有 5 格，要存字符 abcde 并作为 C 字符串使用，够不够。若是独立 length=5 的顺序串，又是什么情况。

核对 A

C 字符串需要 6 格，包括最后的 '\0'；独立长度顺序串只保存这五个字符时可以正好使用 5 格，但必须另有长度信息。两种约定不能混用。

连接、子串和比较都要先规定失败行为

任务 B：固定容量串容量 6，已有 abcd，要连接 xyz。给出三种可能的接口设计：返回失败且不变；截断并报告；扩容。判断哪种才是“正确”，并说明理由。

任务 C：按 0 基 start 和 length 取子串，字符串 abcde 中 start=3,length=2；start=5,length=0；start=4,length=2 分别如何处理。此任务采用“不合法则返回失败，不截断”的契约。

核对 B/C

B 没有脱离契约的唯一行为，关键是调用者知道会发生什么；不能静默越界。C 依次为 de、空串、失败。负长度与负起点同样非法。

堆分配顺序串

“堆分配”在这里指运行时动态申请存储空间，不是排序章节的二叉堆结构。常见表示保存 data 指针、length、capacity，空间不足时另申请较大区域并复制原字符；释放旧空间后，原来的字符地址可能失效。任务：若 length=4、capacity=8，连接 3 个字符是否必然需要扩容？再根据是否预留终止符分别说明依据。

核对动态容量

如果 capacity 表示可用字符格数，7≤8 不需要扩容；若 C 字符串容量 8 包括终止符，7 个数据字符加 1 格终止符也正好够。必须先读清 capacity 的定义，而不是把一种库的细节当成所有顺序串共同约定。

链式串与比较

链式串可一结点一字符，也可一结点一块字符。任务 D：比较长度 1000 的串用“每字符一个指针”和“每块 20 字符一个指针”的额外空间；说明为什么链式插入可能方便，而随机访问某字符仍需顺链查找。

字典序按第一个不同字符确定大小；若前面完全相同，较短串更小。比较的结果不等于长度差，也不等于整串转成数字后的大小。扩展时再研究 Unicode 编码与用户可见字符，这不属于本页简单 ASCII 练习的默认接口。
