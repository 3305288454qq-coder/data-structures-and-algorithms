# R12 用原序号检验排序稳定性

**基础｜编码｜配套深化。学习状态：未开始；材料建立不表示掌握。**

## 为什么练

两个相等整数没有可区分身份；给记录加原序号，才能真的测试稳定性及记录是否丢失。

前置：R01、R02。记录按 key 排序，serial 表示原始下标。实现稳定直接插入；另外写验证器识别不稳定、未排序、丢记录三类错误。

## 接口

`stable_insertion_sort(records)` 原地排序。`is_stable_sort_of(before,after)` 必须同时验证键非递减、记录多重集合未变、每组相同 key 的原有相对顺序未变。serial 唯一但不必按数值递增（用输入实际顺序判断）。

`[(2,40),(1,90),(2,10)]` 的稳定输出是 `[(1,90),(2,40),(2,10)]`。不能把“serial 递增”当成稳定的定义。

## 思考

插入时，碰到相等键到底是继续移动还是停止？选择排序即使每轮找的是第一个最小值，也可能因跨越式交换使别的同键记录倒序。

代码直接给验证器喂正确、同键颠倒、乱序、丢项和重复替换的结果；因此不能用一个总为 true 的函数混过去。稳定性是排序方法与实现共同决定的属性，不是“数组最后升序”就能推出。

## 验收

main 自动核对预期值和边界。退出状态 0：这些测试通过；1：核对失败；2：仍有 TODO。目标算法不可用 std::sort/stable_sort 或整批排序代替；测试中的标准库排序仅作独立参照。测试通过后还需解释复杂度和适用条件。
