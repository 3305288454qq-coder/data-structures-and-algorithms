平时只运行正在练的那一题

在 VS Code 打开并保存目标 .cpp，例如计数排序 R10。

按 Ctrl+Shift+P 打开命令面板，输入“运行任务”，选择 Tasks: Run Task，再选 Run active C++ file。

它会先编译当前保存的源文件，成功后运行其中的 main。main 已经放入自动核对，不要求你先学会编写测试工具。

不要把其他练习的 main 一起编译；每题都是独立程序。

三种结果严格分开

提示 / 状态意思下一步
TODO: implement ... / pending / 退出2至少一个目标函数仍未实现根据题目完成该函数；不是编译器坏了
FAIL: 用例标签 / failed / 退出1已运行，但某条断言失败或出现异常/超时从标签对应的输入、边界和预期检查
PASS: n checks / passed / 退出0该 main 中的 n 条核对通过补自己的测试、解释复杂度，再决定是否记录已核对
compile-failed编译未成功，还没进入自测先看编译错误位置与类型

一个练习可能还有其他边界没有覆盖。测试通过不等于数学证明、所有在线测试通过或已经掌握。

不允许只删 TODO、打印 PASS 或绕过断言来获得通过。测试 main 可以阅读与增加用例，但不要删掉失败用例来掩盖问题。

原有示例输出怎么理解

原49题的问题页仍保留原来的演示调用及相应输出，用于看懂函数行为。

现在实际 main 改为多组自动核对，通常输出 PASS / FAIL / TODO，不再逐行打印那些演示结果。它们不是相互矛盾的两份标准答案。

自动核对在看什么

  • 普通数组题比较返回值、逻辑长度和应当保留的内容。
  • 排序题与标准库排序结果对照；稳定性使用关键字和原序号，不能只看重复整数。
  • 链表与树检查关键连接、结点身份和不变量；这不等于完成了专门的内存泄漏检测。
  • 拓扑等多解题检查合法性，不强制唯一排列。MST权值测试不要求固定的一组边。
  • 新外排序模拟检查输出段、记录数量或归并代价；时间/空间约束仍要结合实现分析。
  • 原49题的断言标签可以查看 测试覆盖记录，新增题以各自 main 与问题页为准。

可选：批量检查工具

批量检查会编译和运行选定练习，生成物只写入本目录 build/checks，不提交或推送 Git。

PowerShell 与当前目录的概念仍适用：编辑器打开了文件，不代表终端就在本目录。

先切换目录。cd 改变当前终端位置；双引号把包含空格的完整路径作为一个参数：

cd "D:\Data Structures and Algorithms"

只检查计数排序：.\ 从当前目录开始；tools\check_practice.ps1 是这里的检查脚本；-Ids R10 指定只检查编号 R10：

.\tools\check_practice.ps1 -Ids R10

若要同时检查多题，-Ids 后用逗号列出编号。例如下面只检查 R10 与 R15：

.\tools\check_practice.ps1 -Ids R10,R15

只有想检查整个资料库时才省略 -Ids。大批 TODO 被标为 pending 是正常的，不要求你先做完它们：

.\tools\check_practice.ps1

默认每个程序超过10秒会被终止并记为失败，避免错误循环一直占用。按需使用 -TimeoutSeconds 30 可将单题上限调到30秒；它不是放宽在线题的时间要求。

报告在 build/checks/latest-results.json，后一次检查会更新这份报告。总结果中只要还有 pending，脚本退出2；不能据此认定所有题运行失败。

导航记录与备份

“未开始、进行中、卡住了、已核对、待复习”由你按实际情况选择。笔记可记录具体测试、理解或卡点。

旧版勾选会带说明迁移为已核对，不升级为“已掌握”。基础、进阶、扩展分开统计。

JSON 是完整备份，能保留状态、笔记与时间；导入前会显示数量，默认保留同编号的本地记录，只有主动勾选覆盖才采用导入版本。

Markdown 是方便阅读的清单；旧版 Markdown 导入只恢复勾选，不承诺恢复所有新式状态与笔记。

数据存在当前浏览器，不能自动同步手机、Notion或另一浏览器；跨设备使用导出/导入。

本页由同目录 Markdown 生成。更新笔记时以 Markdown 为源；页面上的方框用于阅读，实际进度请记在学习记录或导航页。
